# 报告与 brief 的数字一律取终态实测

> 来源：L-2026-09-27-006｜证据：S7 复盘 §3-1、§3-3、§3-5（自报「251 文件 / 17」vs 实测 16 文件 / 235；brief 预期失败计数与实测不符；账本自身一次计数勘误）｜落地：2026-09-28

任何报告（任务报告 / 修复报告 / 阶段报告 / 交接词）或 brief 中出现的数字，必须：

1. 先跑一次取数命令拿到**终态**实测值（如 `git show --stat`、测试运行的用例数、`(Get-ChildItem).Count`）；
2. 把该**取数命令**随数字一并写出，使读者可复算；
3. **禁止**用中间态记忆、上游预估值或「大概」填充数字栏位。

**反例**：报告写「251 文件 / 17 测试」，实测为 16 文件 / 235 用例——数字凭中间态记忆生成，未取终态校准，导致账本与文档双双失真。
