# 有想法先沟通，拿到授权再动手

> 来源：用户当场指令（2026-10-02）｜证据：用户原话「有任何想法要得到我的确认，首要适合我沟通明白，禁止在没得出结论或者得到我授权之前就采取任何写权限的动作」｜落地：2026-10-02

**先沟通清楚，拿到授权，才有写权限。顺序不能颠倒。**

## 三步，缺一不可

1. 有想法 → 用大白话讲清楚 **+ 给出我的倾向**
2. 等用户的**结论或授权**
3. 才动手

**没得出结论、没拿到授权之前，禁止任何写操作。**

写文件、下载、装东西、改配置、建仓库、改注册表、建计划任务——全算写。

## 什么不算授权

**「我自己觉得没问题」不算。** 那只是我的判断，不是用户的点头。判断可以用来让用户更快拍板，不能替他拍板。

## 用户在提问 / 讨论时，不得推进到下一步

> 来源：2026-10-08 用户指令「我在问你问题的时候，没有我的允许不能进行下一步」｜落地：2026-10-08

用户还在**问问题 / 等决策 / 讨论方案** → 答完**停在回答处**，等「继续 / 可以 / 开始」才动手。自动接下一步 = 违反（哪怕只是「继续收尾」）。判据：用户那句是**问题**还是**指令**？前者停，后者动。只读探查用于回答当前问题仍允许。

## 唯一豁免

只读探查不用问：读文件、搜代码、查系统信息、跑 `--version`、看目录列表。

（本条是总则；`no-git-write.md` 是它在 Git 上的具体展开。）

## 真实反例

用户问「有没有更简单的开源实现」，我搜完觉得合适，**没吭声就下载运行了**。用户还等我回答，我先动手了。

一次是疏忽，同一天犯两次就是没规矩兜着。
